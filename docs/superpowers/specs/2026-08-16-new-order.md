# 4.5 New Order — Design Spec

Staff creates a reservation at the counter or by phone.

---

## Overview

A single-page form reachable from the staff dashboard. Staff enters a phone number, optionally a name, picks a date, selects product quantities, and submits. The system creates a `Reservation` with one or more `ReservationItem` rows and optionally creates a new `User`.

---

## Form Layout

One page, top-to-bottom sections. No steps or wizard.

### 1 — Customer

**Phone field** (required)
- Standard `tel` input.
- On `blur`: fires a customer lookup AJAX call to `GET /staff/customers/lookup?phone=…`.
- During the lookup the **Name field is disabled** and shows placeholder "Checking…".
- If found: name field fills with the customer's name and stays disabled (staff cannot accidentally overwrite it).
- If not found: name field enables. A right-aligned hint `← Please enter name` appears inside the field label. The hint disappears as soon as typing begins.
- Name is **not required** — staff can proceed without entering one.

**Name field**
- Enabled/disabled as described above.
- No validation on submit; if blank and the customer is new, the `User` record is created with `name: nil`.

**Source** (visible as a small select or radio beneath the customer fields)
- Populated automatically: if the customer has prior reservations, default to the source of their most recent one.
- If the customer is new, default to `phone`.
- Staff can always change the value.
- Enum values exposed to staff: `phone` and `counter` only (sms/whatsapp/online are not created from this form).

### 2 — Date & Pickup Time

**Date** (required)
- Date picker, minimum value = today.
- Product list does not render until a date is selected.

**Pickup time** (optional)
- Time input, appears next to the date field.
- If left blank, no pickup time is stored.

### 3 — Products

Rendered via a Stimulus controller that calls `GET /staff/orders/products?date=…` on date change.

Three sections in order:

**Available**
- Products scheduled for the selected date with remaining inventory (reserved < batch_size).
- Always visible, no header toggle needed.
- Each row: product name, `{reserved} / {batch_size} reserved · Ready {HH:MM}`, and +/− steppers.
- Steppers start at 0; staff taps + to add.

**Already sold out for {weekday}, {date}**
- Products scheduled for that date where `reserved >= batch_size`.
- Collapsible, starts collapsed. Header shows count e.g. `Already sold out for Friday, Aug 16 (1)`.
- When expanded: a single checkbox at the top of the group reads **"Override inventory to add items anyway"**.
- While the checkbox is unchecked the steppers are rendered but disabled (greyed out).
- Checking the box enables all steppers in this group.

**Not scheduled for this date**
- Products not scheduled for the selected date (no `ProductScheduleDay` record for that weekday, or a `ProductException` marking them unavailable).
- Collapsible, starts collapsed. Header shows count.
- When expanded: same override checkbox pattern as above ("Override — add unscheduled item").
- Steppers start at 0.

If a section has no products it is not rendered.

### 4 — Note

Optional single-line text field at the bottom of the form, below the product list.
Label: "Note (optional)". Maps to `reservations.note` (string, nullable).

### 5 — Submit

Button label: **"Confirm Reservation"**. Disabled while any async operation (lookup, product load) is in progress.

On submit:
1. If the phone number is new, create a `User` with `phone` and `name` (may be nil).
2. Create `Reservation` with `user`, `date`, `pickup_time` (if given), `source`, `note` (if given), `cancelled: false`.
3. Create one `ReservationItem` per product where quantity > 0.
4. Redirect to a confirmation / show page (TBD — can be the dashboard for now).

## Routes & Controllers

```
# config/routes.rb (staff namespace)
resources :orders, only: [:new, :create]
get 'customers/lookup', to: 'customers#lookup'    # returns JSON
get 'orders/products',  to: 'orders#products'     # returns HTML partial
```

New controllers:
- `Staff::OrdersController` — `new`, `create`, `products` (products partial)
- `Staff::CustomersController` — `lookup` (JSON: `{ found: true, name: "…" }` or `{ found: false }`)

---

## Model Changes

### `User`
- Remove `validates :name, presence: true` (name is now optional).

### `Reservation`
- Add `note:string` column (nullable).
- Add `pickup_time:time` column (nullable).

### `DayPresenter` (new query method)
- `DayPresenter#sold_out_products` — scheduled products where reserved >= batch_size.
- `DayPresenter#unscheduled_products` — products not scheduled for the date.
- `DayPresenter#available_products` — already exists; ensure it excludes sold-out ones.

---

## Stimulus Controller

`new-order` controller wires:
- Phone blur → lookup → enable/disable name, set source default.
- Date change → fetch products partial → replace product list region.
- Override checkbox per section → toggle disabled state of steppers in that group.
- Stepper +/− → update hidden quantity inputs.

## Out of Scope

- Editing an existing reservation (4.8).
- Customer-facing reservation flow (4.1).
